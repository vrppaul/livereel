# Tests

- A test holds a behaviour someone can name: it does one thing and checks what came of it. Its name states that behaviour.
- It is written before its code and seen failing. A refactor gets no new test: the old ones pass unchanged.
- At the cheapest level that sees it: `tests/unit/` for what is worked out without a browser — curves, typing, framing, a move's share of its step.
- `tests/smoke/` shoots a film of a page on the disk, in a real browser, and checks which frames were written: never what a frame looks like.
- Never how it looks: no colour, size or pixel read off a frame. A film's look is held by a person's eye, on its contact sheet.
- `tests/scripts/` runs a gate as it is run: as a process, on a file or a repository of its own.
- A test and its helpers hold no branch: no `if`, no conditional expression, no `or`, no filter in a comprehension. Cases of one rule are one test that names every case.
- Data with a shape is a typed model, in tests too.
- The tests are held to formatting alone: no linter, type checker or spelling check reads them.
